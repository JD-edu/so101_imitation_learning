# MuJoCo BC→ACT: 코드·위키독스 대조 및 수정 기록

> 번호 정렬 후 현재 코드 경로는 [장 번호·소스 대응표](chapter_source_numbering.md)를 기준으로 한다. 아래 이전 검토·게시 기록의 101~106 경로는 당시 경로이다. 온라인 1~10장과 최신 통합 원고는 새 경로로 갱신했다.

대상은 `103_mujoco_bc_to_act/`의 201~208 학습·추론 예제와 대응 책 내용이다. 요청의 `103_mujoco_to_act`는 현재 폴더 이름에 맞춰 해석했다. 이번에는 코드 오류를 먼저 수정하고, **[4~10장 통합 원고](chapters_04_10.md)의 5~6장**을 수정본에 맞춰 개정했다. 4장과 7~10장 본문, 0~3장 및 archive 자료는 변경하지 않았다.

온라인 위키독스에 게시한 결과는 아니다. 공개 페이지의 확인 가능한 본문·검색 색인과 로컬 코드를 대조해 게시용 Markdown을 갱신했다. 페이지별 조회 범위는 아래 표에 구분했다. 공개 목차에는 같은 URL이 이전 부록 번호와 최근 4.x 번호로 혼재하므로 제목과 고정 URL을 기준으로 연결한다.

## 2. 확인한 책 설명의 불일치

- RNN 페이지는 시연 명령과 다음 실제 관절 위치를 혼용하고, 3차 smoothstep과 5차 곡선의 명칭을 부정확하게 설명한다. 수정본은 현재 관측 `o_t`, 현재 적용할 명령 `a_t`, 다음 실제 관절 `q_{t+1}`를 구별하고, 실제 사용한 3차식을 설명한다. [대조 페이지](https://wikidocs.net/411448)
- Action Chunking의 시작 잡음 설명에 길이 단위 cm와 각도 rad가 혼재한다. 로컬 XML에서 그리퍼를 포함한 모든 관절이 hinge임을 확인했고 ±0.04 rad를 약 ±2.29°로 설명했다. position actuator의 입력은 위치 명령이다. [대조 페이지](https://wikidocs.net/415320)
- encoder·decoder 설명 중 `z`가 encoder attention에 들어가지 않는다는 내용은 현재 207·208 구현과 다르다. 두 구현 모두 잠재 토큰을 encoder 입력에 연결한다. 개정 원고는 실제 토큰 배열과 shape를 제시한다. [대조 페이지](https://wikidocs.net/415342)
- CVAE는 다양한 행동 스타일을 표현할 수 있으나 누락된 목표 입력이나 외란 복원을 자동으로 해결하지 않는다. 목표 조건과 CVAE의 역할을 나눴으며, 단일 보간 궤적만으로 CVAE의 성능 향상을 입증하지 않는다고 명시했다. [대조 페이지](https://wikidocs.net/417831)
- 공개 RH·TE 설명의 `a(t+1)` 표기는 코드 수정과 함께 현재 적용할 명령 `a_t`로 통일했다. 최신 예측을 더 크게 반영하는 이 구현의 가중치 방향과 에피소드 리셋 규칙도 명시했다. [대조 페이지](https://wikidocs.net/417768)

위 항목은 공개 내용의 요약 대조이며, 새 본문은 로컬 코드에 근거해 작성했다. 공식 ACT와 교육 구현도 구별했다. 원 ACT 구현 참고: [DETRVAE](https://github.com/tonyzhaozh/act/blob/main/detr/models/detr_vae.py). 영상 전처리 참고: [torchvision ResNet18](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html).

## 3. 먼저 수정한 코드 문제

| 문제 | 수정 |
|---|---|
| 모든 학습 단계에서 적용 전 관측에 다음 인덱스의 명령을 연결 | 단일 행동 `actions[t]`, 청크 `actions[t:t+K]`로 정렬하고 마지막 유효 샘플 포함 |
| 목표를 입력하지 않는 202~204·206·208에서 랜덤 목표를 요구 | 고정 목표 과제로 정의. 207은 목표 입력을 유지하며 랜덤 목표 사용 |
| 204·206의 checkpoint 이름 중복 | 206 전용 `action_chunking_rh_te_v2.pt` 사용 |
| 207 학습은 목표 포함 12차원, 기존 추론은 목표 없는 6차원·다른 모델 | 새 `207_ACT_CVAE_infer.py`가 학습 모델을 직접 불러오고 이력 전체에 목표를 결합 |
| 공백 포함 기존 207 추론 파일이 잘못된 checkpoint를 사용 | 기존 이름을 새 추론으로 연결하는 호환 실행 파일로 변경 |
| 206 학습 후 시연은 큐 실행, 별도 추론만 RH·TE | 내장 시연도 매 스텝 재추론·시간 앙상블로 통일 |
| 목표 마커가 없는 `ee_site`를 찾고 마지막 body 위치로 대체 | 실제 XML의 `graspframe` site 사용 |
| 208 사전학습 영상 입력의 채널 정규화 누락 | RGB [0,1] 변환 후 ImageNet mean/std 적용; 학습·추론 모델 공유 |
| 208 추론에도 불필요한 ImageNet 가중치 다운로드 | backbone을 무작위 초기화한 뒤 전체 정책 checkpoint 로드 |
| 영상 수집 시 물리 갱신 직후 파생 위치가 현재 qpos와 다를 수 있음 | 캡처 전에 `mj_forward`로 동기화 |
| 이미지 전체를 float32로 보관 | uint8로 보관해 원본 영상 저장량을 1/4로 축소 |
| 실행 위치에 따라 XML·checkpoint 경로가 달라짐 | 스크립트 위치 기준 절대 경로 사용 |
| 그리퍼 m 단위, 5차식, 토크 외란 등 부정확한 주석·출력 | hinge rad, 3차 smoothstep, qvel 변화로 수정 |

204의 반복적인 배치 shape 출력도 제거했다. 기존 데이터, checkpoint, XML, mesh는 수정하지 않았다. 모델 구조가 같아도 시간 정렬이나 목표 분포가 달라져 기존 학습 결과와 의미가 달라질 수 있으므로 수정된 8단계 모두 새 `_v2.pt` 이름을 사용한다.

## 4. 수정 후 샘플 수

모든 에피소드 길이는 100이다. 학습/평가는 에피소드 기준 80/20이다. 201은 평탄화 이후 분리하지만 현재 설정에서는 에피소드 경계와 일치한다.

| 예제 | 에피소드당 유효 샘플 | 학습 | 평가 |
|---|---:|---:|---:|
| 201 MLP | 100 | 8,000 | 2,000 |
| 202 RNN·203 Transformer | 91 | 7,280 | 1,820 |
| 204~206 chunk | 62 | 4,960 | 1,240 |
| 207 goal CVAE | 62 | 19,840 | 4,960 |
| 208 visual CVAE | 71 | 11,360 | 2,840 |

재현 명령은 저장소 루트 기준이다.

```bash
MUJOCO_GL=egl PYTHONDONTWRITEBYTECODE=1 \
/home/robo/anaconda3/envs/lerobot/bin/python -m unittest discover \
  -s tests -p test_mujoco_bc_to_act.py -v
```

**회귀 검사 11개 통과, 실패·오류·skip 0개.** 수정 후 Python 18개 구문 검사를 통과했고 기존 자산 41개(가중치 8개 포함)의 해시가 유지됐다.

[회귀 검사 코드](../tests/test_mujoco_bc_to_act.py), [검증 결과·파일 해시](mujoco_bc_to_act_verification.json), [실행 로그](mujoco_bc_to_act_test_output.txt)를 함께 제공한다.

- 201~208의 모델 8개에서 작은 배치로 역전파와 optimizer 갱신, 메모리 내 checkpoint 저장·strict 로드, eval 출력 일치 및 재현성 확인.
- 201~207에서 실제 MuJoCo로 단계별 2에피소드 × 100스텝 수집, 텐서 크기·유한값·목표 조건 확인.
- 식별 가능한 합성 배열로 모든 Dataset의 첫/마지막 샘플, 행동 정렬, 에피소드 경계 및 샘플 수 검사.
- 206 내장 학습 후 시연의 매 스텝 재추론과 시간 앙상블·리셋도 대체 GUI에서 검사.
- 206·207·208 별도 추론 루프의 GUI와 정책 출력은 대체해 122스텝 실행. 시간 앙상블 계산과 120스텝 리셋, 207의 목표 이력 갱신 검사. 실제 학습 정책의 성공률 실험은 아님.
- 208에서 EGL context로 **실제 RGB 64프레임** 생성(2에피소드 × 32스텝), uint8·크기·고정 목표·Dataset 연결 검사. 기본 20,000프레임 전체 수집은 아님.
- 목표 마커의 순기구학 좌표가 `graspframe`과 일치하는지 확인.
- 기존 이미지·XML·mesh·가중치의 해시를 수정 전과 비교해 보존 확인. 테스트 중 기존 checkpoint를 쓰지 않음.

## 6. 남아 있는 실험 조건

기본 epoch 전체의 재학습, 실제 GLFW 창을 사람이 조작하는 평가, 실제 모터 구동은 수행하지 않았다. v2 가중치는 사용자가 각 학습 파일을 실행해 생성해야 한다. 오류 수정 검증 결과를 목표 도달·외란 복원 성공으로 표현하지 않는다.

기본 `timestep=0.002`이며 명령마다 물리를 한 번 진행하므로 100스텝 시연은 0.2초이다. 마지막 명령이 목표와 같아도 실제 로봇의 도달은 별도 문제이다. 이번에는 물리 timestep·actuator 파라미터·XML을 바꾸지 않았으며 책에 시뮬레이션 시간과 화면 시간의 차이, 동역학 추종 오차를 명시했다.

초기 이력은 같은 초기 관측을 반복하지만 학습에는 패딩하지 않은 윈도우를 사용한다. 208은 전역 영상 토큰 하나를 사용하는 단순 P2P 과제이다. 이러한 설계 제한은 코드와 같은 내용으로 설명했으며, 일반 물체 조작이나 공식 ACT 재현 성능으로 확대 해석하지 않는다.

## 7. 후속 게시 완료

이 보고서 작성 후 사용자의 게시 요청으로 개정 4~10장을 위키독스에 장별 공개 게시했다. 기존 원고는 원문과 URL을 유지하며 보관함으로 이동했다. 연결 도구를 통해 게시 직전 원문 전체를 백업했으며 [게시 기록](wikidocs_publication.md)에 링크와 보존 검증 결과가 있다. 위의 공개 웹 조회 제한은 최초 대조 작업 당시의 기록이다.
