# MuJoCo 기본: 소스코드·위키독스 대조 및 원고 개정

> 번호 정렬 후 현재 코드 경로는 [장 번호·소스 대응표](chapter_source_numbering.md)를 기준으로 한다. 아래 이전 검토·게시 기록의 101~106 경로는 당시 경로이다. 온라인 1~10장과 최신 통합 원고는 새 경로로 갱신했다.

> 아래는 코드 보존 조건으로 수행했던 이전 검토 기록이다. 이후 요청에 따라 센서 주소·위치 제어·변환 출력명을 수정하고 MuJoCo 본문을 온라인 3장에 통합했다. 현재 결과는 [1~4장 동기화 보고서](chapters_01_04_sync_review.md)를 기준으로 한다.

검토 대상은 학습 단계 2의 `102_mujoco_basic/`이다. 기존 통합 원고의 **4장만** 교체했으며, 기존 PyTorch 2장이나 통합 원고의 5~10장을 바꾸지 않았다. 개정 본문은 [4~10장 통합 파일](chapters_04_10.md#4장-mujoco-기초와-로봇-모델-실행)에 있다.

현재 결론은 **책과 코드가 완전히 일치하지 않는다**이다. 일부는 책의 개념·확장 예제와 실제 실행 파일이 다르고, 일부는 코드 자체의 결함을 책이 그대로 설명하고 있다. 개정 원고는 실제 구현을 기준으로 파일·이름·수치·실행 순서를 맞추되, 발견된 코드 결함을 올바른 동작이라고 설명하지 않도록 했다.

기존 요청의 코드 보존 조건을 유지했다. Python/XML/URDF/mesh는 변경하지 않았고 수정 방향은 원고의 별도 코드 조각으로 표시했다. **온라인 위키독스 페이지는 수정하지 않았다.**

## 1. 온라인 확인 범위와 한계

공개 목차 및 아래 페이지를 확인했다. 조회된 책 목차에는 이전 10장, 센서 페이지의 목차에는 새 3장 번호가 나타났다. 캐시 시점이 다른 응답을 현재의 단일 확정 목차라고 단정하지 않고, 페이지 ID와 제목으로 대응시켰다.

## 2. 확인된 차이와 반영 사항

아래에서 **코드·원고 보완**은 온라인 원문의 오류라고 단정하는 항목이 아니다. 특히 온라인 접근이 실패한 절은 로컬 구현에서 확인한 사실만 기재했다.

| 항목 | 확인된 근거 | 원고 반영 |
|---|---|---|
| 경로 변경 | 위키독스 참조 링크에는 `105_MUJOCO_basic`이 남아 있음 | 현재 로컬 경로 `102_mujoco_basic`으로 실행 안내 통일. 아직 게시하지 않은 GitHub 경로가 존재한다고 가정하지 않음 |
| 101 창·종료 | 실제 640×480, 모델 없음, ESC callback 없음 | 빈 창이 정상 결과이며 창 닫기 사용. 코드 주석과 실행문 구분 |
| 102 프레임 시간 | `data.time`을 1/60초 이상 전진, 실제 60Hz 대기 없음 | 시뮬레이션 시간과 벽시계 FPS 구별. 기존 [MJCF 절](https://wikidocs.net/371947)의 설명 보완 |
| 103 명령 일정 | `<10: (10,10)`, `<20: (10,-10)`, 이후 0 | “좌·우회전 반복” 주석 대신 실제 일회성 벽시계 일정 설명 |
| 104~106 모델 선택 | 104는 기본형 scene, 105~106은 enhanced scene | 파일별 include 대상을 표에 명시 |
| 105/106 좌우 속도 | `velocity=40`, 왼쪽에 0.7 곱함 | W 최종 명령 28/40 및 출력 로그 40/40의 차이 명시 |
| 입력·물리 순서 | 105/106에서 `mj_step` 다음에 새 `ctrl` 대입 | 다음 물리 스텝에 반영된다고 설명 |
| IMU 주소 결함 | 106 gyro ID=1, 주소=3; 코드와 [센서 절](https://wikidocs.net/371967)은 ID로 slice | 현재 코드의 잘못된 읽기와 `sensor_adr`를 사용하는 개선 조각을 분리 |
| IMU와 LiDAR 범위 | 로컬 XML에 rangefinder 없음 | LiDAR는 미구현 확장으로 구분. 로컬 Z축 측정 방향 설명 |
| 자료 구조·PD 일반화 | [API 부록](https://wikidocs.net/371969)은 PD 값을 ctrl에 넣는 일반 예시 제공 | 실제 모델의 actuator 종류에 따라 해석, free joint의 nq/nv 차이 설명 |
| JDCobot100 제어 | position actuator에 Python PD 값 입력; [온라인 실습](https://wikidocs.net/372030)도 문제를 지적 | 온라인 지적을 유지하고 실제 파일과 연결. 토크 제어의 완성 예제라고 소개하지 않음 |
| JDCobot 변환 출력 | 스크립트는 `jdcobot200.xml` 저장, 로그·scene은 `jdcobot100.xml` | 입력·실제 출력·후속 include 불일치 표시 |
| Puppy 기능·이름 | [온라인](https://wikidocs.net/372089)은 사인파·자세 전환 예시 및 `act_lf_joint1`; 로컬은 초기 자세 유지, `act_lf_j1` | 본편을 실제 구현 기준으로 변경 |
| SO-101 모델 | [온라인](https://wikidocs.net/372090)에 JDCobot형 4관절 개념 예시와 별도 실행 파일명 | 로컬 6관절·6 actuator와 실제 세 파일 기준으로 변경. 개념 예시를 동일 구현이라고 취급하지 않음 |
| SO-101 이득 | 동일 default 안 반복 선언; 컴파일된 kp=998.22, kv=2.731 | 첫 선언값과 최종 적용값 구분; ctrl 제한 활성 여부 명시 |
| URDF 재변환 | 세 URDF를 직접 변환하면 모두 actuator 0개 | 완성 XML과 변환 결과 구별, 108/109 원본 XML 덮어쓰기 설명 |
| Onshape 범위 | 제공된 URDF/mesh는 존재, export `config.json`은 없음 | 외부 CAD 과정과 저장소 안 재현 가능한 실습 구분 |

## 3. 로컬 검증

검증 환경은 Python **3.10.12**, MuJoCo **3.10.0**이다. 결과를 [mujoco_basic_verification.json](mujoco_basic_verification.json)에 기록했다.

- Python 파일 **15개** AST 문법 검사 통과.
- 실제 실행 파일이 읽는 모델 **8개** 로드 성공. 각각 0 명령으로 100스텝 진행한 뒤 qpos/qvel이 유한함을 확인.
- URDF **3개** 로드·임시 XML 저장 성공. 원래 변환기를 실행하지 않고 `/tmp`에 출력해 완성 모델 보호. 세 모델 모두 변환 직후 `nu=0`.
- 105/106 소스의 키보드 명령 계산 AST를 분리 실행해 W/S/A/D/무입력 값 확인. GUI 코드나 모터 통신은 실행하지 않음.
- 실제 106 모델의 센서 ID·주소·차원을 확인하고, 식별용 가상 센서 배열에서 잘못된 gyro slice를 재현.
- 실제 컴파일된 SO-101 actuator의 이득·bias·force/ctrl 제한값 확인.
- 기존 소스·자원 **203개**의 작업 전후 SHA-256 일치 확인.
- 통합 원고는 4장 본문만 교체. 4장 앞의 안내와 5~10장 이하 텍스트가 작업 전과 동일함을 확인.
- 본문 코드블록 문법, 로컬 링크, 실행 파일 경로 및 추가 진단 예제 확인.

**검증의 한계:** 0 명령으로 100스텝이 안정적이라는 결과는 기존 PD 제어 루프의 안정성 검증이 아니다. GUI 창, 실제 키 이벤트, overlay 렌더링, CAD 서비스, 온라인 편집은 실행하지 않았다. 가상 센서 배열 실험은 배열 주소를 확인하는 실험이며 실제 자세 측정 실험이 아니다.

## 4. 남아 있는 소스코드 개선 항목

이 항목들은 발견했지만 코드 보존 요청에 따라 적용하지 않았다.

1. `106_mujoco_imu_sensor.py`: 센서 ID 대신 `sensor_adr`와 `sensor_dim`으로 값 읽기.
2. 107/109 `robot_move.py`: position actuator에 맞는 목표 위치 입력으로 변경하거나, 직접 토크 제어를 위한 actuator 설계로 일관되게 변경.
3. 107 `urdf_to_mjcf.py`: 출력 파일명·성공 메시지·scene include의 일치 및 결과 덮어쓰기 정책 정리.
4. 101/103의 주석과 실제 종료·반복 동작 불일치 정리.
5. 104~106의 viewport 갱신 및 제어 주기 개선은 별도 기능 변경으로 취급.

원고에 예시 개선 조각이 있다는 이유로 위 항목들이 이미 수정되었다고 보지 않는다. 이번 결과물은 **소스 기준으로 정확해진 책 원고와 대조 보고서**이다.
